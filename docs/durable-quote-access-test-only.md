# Durable quote access: isolated test-only composition

Adds an opt-in composition around existing-session proof, persisted membership/version checks, per-event grants and quote operations using one PostgreSQL transaction. It does not start a server, install an authentication adapter or provision accounts, sessions, permissions, catalogs or credentials. The prepared migration is not registered with existing startup paths and permits only `test` mode.

The session adapter must be server-owned. Do not resolve an actor, tenant or permission from a request body or untrusted identity header. The database stores hashes rather than raw proof tokens. Quote data remains sealed through the existing vault. Authority rows remain share-locked until the quote transaction commits. Revocation serializes after a transaction that already holds the lock; subsequent requests are rejected. Expiry during the operation causes rollback. This does not promise cancellation of a transaction that already acquired valid authority.

Creation requires an existing, explicitly assigned event ID and grant; a quote record need not exist yet. This slice does not allocate event IDs or create assignments. Without the Dashboard opt-in, status reports role-level capability only; every event operation additionally requires the event grant. With the fixed-event Dashboard opt-in, status also requires that event grant. FINANCE is not allowed to access this quote module. These are test policies, not configured permissions for real Gourmet staff.

Independent review found an availability issue: an indefinitely pending business callback could retain the authority locks and pooled connection. The corrective work adds a monotonic transaction deadline including acquisition, server-side statement/idle timeouts compatible with PostgreSQL 16, and permanent destruction of an interrupted lease. The pool must itself configure a finite connectionTimeoutMillis (1–30000 ms) to bound its pending acquisition queue; pipeline mode and pool onConnect/verify hooks are unsupported. The default request deadline is 5000 ms; repository-only test configuration permits 1–30000 ms. An already executing PostgreSQL statement can retain locks until the server observes disconnection or its configured statement_timeout expires; the application deadline is not a guarantee of instantaneous physical lock release. Arbitrary JavaScript callbacks are not forcibly terminated: any late continuation only retains a closed client and must not perform external side effects. Catalog adapters remain trusted, bounded providers; using the same constrained pool recursively may time out.

No COMMIT may be issued after an observed deadline. If a timeout or connection failure occurs after COMMIT was already sent, the database outcome can be uncertain: the API returns a sanitized failure and the caller must retry the existing idempotency key. Do not promise rollback for that uncertain-commit case. The ordinary expiry-before-COMMIT path rolls back quote, audit and receipt together.

## Fixed-event Dashboard projection (opt-in test composition)

Passing `dashboardEventId` to `createDurableTestQuoteApi` registers `GET /api/office/event-quotes/dashboard/access`. Omitting it leaves the route unregistered. The ID is fixed by the server composition; request bodies, query selectors, identity headers and client event names cannot select its scope or authorize an event. A pre-existing active assignment and event grant are required even before the quote record is created. There is no event directory or grant provisioning path.

The projection resolves the supplied existing-session proof and authorizes `read` on that fixed event using the same PostgreSQL transaction and locks as quote operations. It derives read/write/approval from that grant and role restrictions, asks the catalog adapter for the authenticated workspace, and limits the view to the earliest session, membership, grant, catalog or 15-minute presentation deadline. Mode remains `test`; the catalog must be `test_only`. An unavailable catalog or expired authority never returns a ready projection. Response security/origin guards and `no-store` apply before session resolution.

`identityKey` and `serverRevision` are the same opaque, non-secret version. A repository-private, process-local random key seals the session proof hash, membership identity/version, account/session versions, role and grant/assignment state into an opaque revision. No stored proof hash, raw session token, actor ID, membership ID or CSRF token is serialized in the projection. Session rotation, effective permissions/windows, membership and assignment changes alter the revision; restarting the API invalidates previous presentation revisions without losing durable data. This revision grants no authority and is not a credential.

`createDashboardQuoteAccessSource` is an explicit same-origin HTTP adapter. It sends no chosen identity, tenant or event and requires a durable single-event test projection. Its caller must supply the existing host's synchronous withdrawal subscription. The source does not log in, create a session, install a database listener or poll for revocations. The host closes views immediately on a known withdrawal; an unannounced database change is enforced on the next server request, while the existing UI expiry timer closes the projected view at its deadline.

The bound quote client sends the non-secret revision in `x-event-quote-access-revision` for status, read and command requests. The server requires it for Dashboard-opt-in writes and compares it against freshly locked authority before business execution, preventing a changed session or an omitted revision from executing an old view's command. Status/read/command JSON also echoes the revision; mismatches, missing revisions, aborts and obsolete UI generations cannot restore content. CSRF still comes from the existing server/session owner through the quote status contract. Artifact links remain separately authorized by the current session and event grant. The ordinary API composition retains its previous response shape when the Dashboard option is absent.

The isolated browser harness now seeds only synthetic SQL session/membership/assignment/grant rows, injects server-owned proof into `createDurableTestQuoteApi`, and uses the HTTP Dashboard source without fabricated browser authority. It covers create → quote → internal approval → API recreation → recovery, obsolete brief/v2, artifact isolation, a real event read held behind an explicit release barrier until the view closes, navigation, SQL session revocation, shorter session lifetime, persisted read-only denial and grant expiry/revocation. The expiry case advances coordinated server/browser test clocks only after the record has loaded; it does not depend on a three-second CI timing window. Revocation notifications in this laboratory harness model the host lifecycle signal; they do not pretend to be a production SQL subscription.
